# 해시 함수와 체이닝

`mini_redis/hashmap.py`가 키를 어느 칸에 넣고, 같은 칸에 키가 몰리면 어떻게 이어 붙이는지 정리한다. 아래 숫자는 이 저장소의 `fnv1a_hash`로 직접 계산한 값이다.

## 1. 해시 함수: 키 → 칸 번호

칸(버킷)이 8개인 표(`HashMap()`의 기본 크기)에 키를 넣을 때 어느 칸에 넣을지 계산한다.

```
키 ──UTF-8 바이트──▶ FNV-1a(32비트) ──▶ 해시값 ──% 칸 수──▶ 칸 번호
```

바이트마다 같은 세 단계를 반복하고, 결과 h가 다음 바이트의 시작 h가 된다(`mini_redis/hashmap.py:22-26`).

```
h = 2166136261                      # 시작값
바이트마다:  h = h XOR 바이트        # 비트 섞기
             h = h × 16777619        # 소수 곱해 퍼뜨리기
             h = h & 0xFFFFFFFF      # 32비트로 자르기
```

| 키 | UTF-8 바이트 수 | 해시값 | 칸 8개일 때 |
|---|---|---|---|
| user:1 | 6 | 1830439627 | 3 |
| user:2 | 6 | 1847217246 | 6 |
| 키 | 3 (`ed 82 a4`) | 2650650782 | 6 |

- 같은 키는 언제나 같은 칸이다. 찾을 때도 같은 계산으로 그 칸에 바로 간다(`mini_redis/hashmap.py:57-58`).
- 한글은 한 글자가 3바이트라서 `키`는 세 번 돈다. 글자가 아니라 바이트 단위라 결과가 늘 같다.
- 마지막 글자 하나만 달라도 해시값이 달라져 키가 여러 칸으로 퍼진다(user:1 → 3, user:2 → 6).
- 파이썬 `hash()`는 실행할 때마다 문자열 해시값이 바뀌어서 쓰지 않는다.

## 2. 충돌과 체이닝

칸 수는 정해져 있고 키는 끝이 없어서, 다른 키가 같은 칸을 받는 일(충돌)이 생긴다. 위 표에서도 `user:2`와 `키`가 둘 다 6번 칸이다.
체이닝은 칸마다 리스트를 달아 같은 칸의 키를 줄줄이 이어 붙이는 방법이다.

```
칸[3] → [user:1]
칸[6] → [user:2] ⇄ [키]      ← 같은 칸이면 뒤에 이어 붙임
나머지 → None                 (키가 처음 들어올 때 리스트를 만든다)
```

- 찾기: 칸 번호를 계산하고, 그 칸의 리스트만 앞에서부터 키를 비교한다(`mini_redis/hashmap.py:60-68`).
- 넣기: 같은 키가 있으면 값만 바꾸고, 없으면 리스트 끝에 붙인다(`mini_redis/hashmap.py:70-79`).
- 지우기: 찾은 노드를 떼어 내고 앞뒤 노드를 다시 잇는다.
- 칸 안의 리스트는 LRU 순서에 쓰는 것과 같은 이중 연결 리스트(`mini_redis/dlist.py`)다. 노드가 `prev`로 앞 노드를 알아서 떼어 내기가 O(1)이다.
- 로드 팩터(키 수 ÷ 칸 수)가 0.75를 넘으면 칸을 2배로 늘리고 모든 키를 다시 나눠 넣는다(`mini_redis/hashmap.py:78-79`). 그래서 칸당 키는 평균 0.75개 이하다.
- 칸이 16개가 되면 `user:1`은 11번, `user:2`와 `키`는 둘 다 14번이다. 칸을 늘려도 같은 칸일 수 있어서 체이닝은 계속 필요하다.
